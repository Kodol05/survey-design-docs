# UI 설계 — 시각 기반과 화면 규격

작성일 2026-08-23

이 문서는 **"어떻게 생겼나"** 만 다룹니다. 무엇이 어디 있고 어떻게 동작하는지는 `01-features-ux.md`에 있고, 여기서 다시 쓰지 않습니다.

01에 이미 확정된 것 — 경쟁사 분석(§1), 7점 척도와 라벨(§2.2), 반응형 정책(§2.3), 접근성(§2.4), 자동저장(§2.6), 관리자 정보 계층(§4.1). **이 문서는 그 위에 색·간격·부품 규격을 얹고, 08·10에서 새로 생긴 화면을 채웁니다.**

## 0. 먼저 — 기존 설계와 충돌하는 것 두 개

08·10의 내용을 그대로 넣으려면 `00`·`01`의 확정 사항 두 개를 뒤집어야 합니다. 여기서 결론만 적고, `00`에 정식으로 옮기는 것은 별도로 합니다.

### 충돌 1 — 상관 표시 금지

`01` §4.5와 `00` §6에 이렇게 적혀 있습니다.

> 상관계수·회귀선 **표시 안 함** — n≤50에서 상관 추정은 매우 불안정
> 척도 간 상관분석 ❌ — 50명이면 매우 불안정

그런데 08의 관련도 표, 10의 사내 관련도·순위·계산식이 전부 상관입니다. **핵심 기능이 금지 항목에 걸려 있습니다.**

**결론: 금지를 풉니다. 대신 가드를 UI에 못 박습니다.**

당시 금지한 것은 *성향 축끼리*의 상관이었고, 그건 볼 이유가 없어서 뺀 것입니다. 지금은 *성향 × 직무능력*이고 이게 제품 자체입니다. 다만 **불안정하다는 지적 자체는 그대로 유효합니다.** 그래서 01이 "안 보여줌"으로 피했던 부담을 이 문서가 대신 집니다 — 아래 §2.2의 n 배지와 §3.4의 다중비교 경고는 선택이 아니라 필수입니다.

### 충돌 2 — 개인 화면의 사내 위치

`00` D-09는 **개인 화면에 사내 상대위치를 절대 표시하지 않는다**로 확정돼 있습니다. 이유가 탄탄합니다 — 상대위치는 사람이 늘 때마다 바뀌는데 개인 결과는 스냅샷으로 고정되므로, 30명 근처에서 먼저 본 사람과 나중에 본 사람이 영구적으로 다른 화면을 보게 됩니다.

그런데 `07`의 개인 결과 화면 표에 `능력 | 내 점수 | 사내 위치`가 있습니다.

**결론: D-09를 유지하고 `07`을 고칩니다.**

08이 말하는 "우리 회사 안에서 비교"는 관리자 화면 얘기로 읽으면 충돌이 없습니다. 개인은 원점수와 만점 대비 %만 봅니다.

### 같이 정한 것

**사내 분포 위치를 P2에서 P0으로 올립니다.** 08에 차별점 세 개 중 하나로 적힌 것을 후순위에 둘 수 없습니다. 계산은 정렬 한 번이라 비용도 작습니다. 단 `n < 30`이면 위치 대신 안내 문구를 띄웁니다(D-24).

## 1. 시각 기반

### 1.1 색

브랜드가 따로 없으므로 **검증된 기본 팔레트를 그대로 채택**합니다. 색맹 대응과 대비를 자동 검사기로 통과시킨 값이라, 임의로 고르는 것보다 안전합니다.

**계열 색** — 순서가 고정입니다. 돌려쓰지 않습니다.

| 슬롯 | 쓰는 곳 | 값 |
|---|---|---|
| 1 파랑 | 본인 · 주 계열 | `#2a78d6` |
| 2 주황 | 사내 평균 · 비교 대상 | `#eb6834` |
| 3 청록 | 세 번째가 필요할 때 | `#1baf7a` |

셋까지는 산점도처럼 모든 쌍이 동시에 보이는 화면에서도 검사를 통과합니다. **넷째부터는 쓰지 않습니다** — 화면을 나누거나 "기타"로 묶습니다.

> 청록은 밝은 배경에서 대비가 2.74로 3:1에 못 미칩니다. 이 색을 쓰는 자리에는 **글자 라벨을 반드시 같이** 둡니다.

**발산 색 — 상관 표 전용**

상관은 −1에서 +1이고 0이 의미 있는 가운데입니다. 단색 계열을 쓰면 **강한 음의 상관이 그냥 "낮은 값"으로 보입니다.** 그래서 양쪽으로 갈라지는 색을 씁니다.

```
  −1                    0                    +1
  빨강 ◀──────────── 회색 ────────────▶ 파랑
  #d03b3b           #f0efec            #2a78d6
```

양쪽 단계 수를 같게 둡니다. 가운데에 색을 넣지 않습니다.

**상태 색** — 계열 색과 겹치지 않게 따로 둡니다. 항상 아이콘이나 글자와 같이 씁니다.

| | 값 | 쓰는 곳 |
|---|---|---|
| 양호 | `#0ca30c` | 응답 품질 정상 |
| 주의 | `#fab219` | n 부족, 신뢰구간 넓음 |
| 경고 | `#ec835a` | 다중비교, 과적합 |
| 위험 | `#d03b3b` | 응답 품질 미달 |

**바탕과 글자**

| 역할 | 값 |
|---|---|
| 카드 바탕 | `#fcfcfb` |
| 페이지 바탕 | `#f9f9f7` |
| 본문 글자 | `#0b0b0b` |
| 보조 글자 | `#52514e` |
| 흐린 글자 (축·라벨) | `#898781` |
| 격자선 | `#e1e0d9` |
| 축선 | `#c3c2b7` |
| 테두리 | `rgba(11,11,11,0.10)` |

**다크 모드는 1차 범위 밖입니다.** 다만 색을 전부 CSS 변수로 선언해서, 나중에 값만 갈아끼우면 되게 둡니다.

### 1.2 글자

01 §2.3이 정한 대로 고정 px을 쓰지 않습니다. 글꼴은 `system-ui, -apple-system, "Segoe UI", sans-serif` 하나만 씁니다.

| 역할 | 크기 |
|---|---|
| 화면 제목 | `clamp(1.5rem, 1.3rem + 0.8vw, 2rem)` |
| 구역 제목 | `clamp(1.125rem, 1rem + 0.4vw, 1.375rem)` |
| 문항 본문 | `clamp(1rem, 0.9rem + 0.4vw, 1.25rem)` |
| 일반 본문 | `1rem` |
| 표 안 글자 | `0.875rem` |
| 축·보조 | `0.8125rem` |

**표와 축의 숫자에는 `font-variant-numeric: tabular-nums`를 겁니다.** 자릿수가 세로로 맞아야 훑어볼 수 있습니다. 큰 낱개 숫자(응시 완료 인원 같은 것)에는 걸지 않습니다.

### 1.3 간격

4px 단위로만 씁니다. Tailwind 기본 눈금과 같습니다.

`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`

중간값을 만들지 않습니다. 화면마다 간격이 달라지는 원인이 대부분 여기입니다.

### 1.4 데이터 밀도 — 화면마다 반대로 갑니다

이게 이 시스템에서 제일 중요한 판단입니다.

| | 응시 화면 | 관리자 표 |
|---|---|---|
| 보는 시간 | 20분 내리 | 훑어보고 지나감 |
| 한 번에 | 문항 몇 개 | 50명 전부 |
| 행 높이 | 넉넉히 | **32px** |
| 폭 | `max-width` 제한 | 전체 폭 |

관리자 표를 여유 있게(50px) 잡으면 한 화면에 다섯 명밖에 안 들어옵니다. 50명을 훑는 게 목적이므로 조밀하게 갑니다. 반대로 응시 화면을 조밀하게 만들면 20분이 훨씬 길게 느껴집니다.

### 1.5 읽기 폭 제한은 **글자에만** 겁니다

`01` §2.3이 정한 `max-width`는 **글줄 길이 때문**입니다. 한 줄이 길어지면 다음 줄 첫 글자를 찾느라 눈이 헤맵니다. 한국어는 한 줄 40~50자가 상한입니다.

**이 규칙은 글자에만 해당합니다.** 척도 줄, 표, 차트는 글이 아니라서 줄 길이 문제가 없습니다. 같은 컨테이너에 묶으면 넓은 화면에서 가운데만 쓰고 양옆이 비게 됩니다.

```
┌────────────── 페이지 폭 ──────────────┐
│        ┌─ 44rem ─┐                   │
│        │  문 항   │  ← 글자만 제한      │
│        └─────────┘                   │
│  ⬤    ●    ○   ·   ○    ●    ⬤      │  ← 제한 없음
└──────────────────────────────────────┘
```

| 영역 | 폭 |
|---|---|
| 문항·서술문 | `max-width: 44rem` |
| 척도 줄·표·차트 | 컨테이너 전체 |
| 응시 화면 컨테이너 | `80rem` |
| 관리자 | 전체 폭 + 가로 스크롤 |

## 2. 공통 부품

### 2.1 분포 위치 막대

`관리자 개인 상세`, `직무능력 옆 병기`, `사내 분포` 세 군데에서 쓰입니다. **규격이 하나여야 합니다.**

```
협력   75    ▁▁▁▃▅█▇▄▂▁      사내 위치: 위쪽
              └──────┘ ▲
                       이 사람
```

| 규칙 | |
|---|---|
| 축 | 0~100 고정. 자동 눈금 금지 |
| 표현 | `위쪽 / 가운데 / 아래쪽` 세 단계. 백분위 숫자는 안 씁니다 |
| n < 30 | 막대 대신 `아직 비교할 만큼 모이지 않았습니다` |
| 개인 화면 | **표시하지 않음** (D-09) |

세 단계로만 표현하는 이유는 백분위 숫자가 사람이 늘 때마다 흔들려서, 정밀해 보이는 만큼 신뢰를 잃기 때문입니다.

### 2.2 n 배지

상관이 나오는 **모든 자리**에 붙습니다. 예외 없습니다.

```
   +.42                       ← 이렇게 두면 안 됩니다
   +.42  n=43  .13~.64        ← 이렇게 둡니다
```

같은 `.30`이라도 500명이면 확실하고 43명이면 거의 의미가 없습니다. 숫자만 놓으면 보는 사람이 그 차이를 알 수 없습니다.

| 상태 | 표시 |
|---|---|
| 신뢰구간이 0을 안 넘음 | 보통 표시 |
| 0을 넘음 | **흐리게** + 주의 색 점 |
| n < 30 | 값 자체를 감추고 `n 부족` |

### 2.3 경고 배지

계산식 화면과 신뢰도 화면에 붙습니다. 아이콘 + 글자를 같이 씁니다. 색만으로 표시하지 않습니다.

| | 문구 |
|---|---|
| 다중비교 | `탐색용입니다. 우연히 높게 나온 값이 섞여 있을 수 있습니다` |
| 과적합 | `이 회사 데이터로 만든 식이라 실제 오차는 더 큽니다` |
| 신뢰도 미달 | `이 척도는 아직 안정적이지 않습니다` |

### 2.4 세 가지 상태 표기

관련도 표의 칸은 세 상태입니다. **색으로는 뒤 둘을 구분할 수 없으므로 글자로 씁니다.**

| 표기 | 뜻 | 칸 색 |
|---|---|---|
| `+.28` | 연구에서 관련이 나옴 | 발산 색 |
| `없음` | 확인했는데 관련이 없었음 | 중립 회색 |
| `—` | 연구된 적이 없음 | 바탕색 + 흐린 글자 |

### 2.5 그 외

| 부품 | 규격 |
|---|---|
| 버튼 | 높이 44px(주 동작) / 36px(보조). 터치 타깃 44×44 유지 |
| **구역** | **테두리도 바탕색도 두지 않는다.** 제목 + 그 아래 가는 선 + 넉넉한 여백으로만 나눈다 |
| 표 | 감싸는 테두리 없음. 머리행 아래와 행 사이 가로선만 |
| 빈 상태 | 아이콘 없이 한 문장. `아직 응시한 사람이 없습니다` |
| 입력칸 | 여기는 테두리를 남긴다. 어디를 눌러야 하는지가 보여야 한다 |

### 왜 상자를 두르지 않는가

요소마다 테두리와 바탕색을 두면 **화면이 상자 모음으로 보입니다.** 실제로 나뉜 것도 아닌데 나뉜 것처럼 읽히고, 흔한 관리자 템플릿과 똑같아집니다.

**바탕은 한 톤입니다.** `--page`와 `--surface`가 같은 값(`#fcfcfb`)입니다. 아주 가끔 살짝 눌러야 할 때만 `--wash`(`#f3f2ee`)를 쓰고, 그때도 테두리는 두르지 않습니다.

| 나누는 수단 | 쓰는 곳 |
|---|---|
| **여백** | 기본. 구역 사이 56~80px |
| **제목 + 아래 가는 선** | 구역 머리 |
| 왼쪽 세로선 | 경고·안내처럼 흐름에서 살짝 뺄 때 |
| 옅은 바탕(`--wash`) | 숫자 카드처럼 값이 주인공일 때 |
| ~~감싸는 테두리~~ | **쓰지 않음** |

## 3. 차트 규칙

공통으로 지키는 것 — **선은 2px, 점은 8px 이상, 격자는 흐리게, 값 라벨은 전부가 아니라 골라서.** 계열이 둘 이상이면 범례를 항상 두고, 색 하나로만 구분되게 두지 않습니다.

### 3.1 레이더 — 7축 개인 결과

01 §3.6에 이미 정해져 있습니다. 여기서 더할 것 하나.

**사내 평균을 겹칠 때** 본인은 슬롯 1(파랑) 채움, 사내 평균은 슬롯 2(주황) **점선 테두리만**. 둘 다 채우면 겹친 부분이 안 읽힙니다. 관리자 화면에서만 겹칩니다.

### 3.2 상관 표

가장 중요한 화면입니다.

```
             협력      자율적 실행
  위험회피   −.25       −.36
             n=43       n=43
  사회적     −.34        —
   민감성    n=43
  인내력     +.28       +.14
             n=43       n=43        ← 신뢰구간이 0을 넘으면 흐리게
```

| 규칙 | 이유 |
|---|---|
| 칸 안에 **숫자를 직접** 적음 | 색만으로는 값을 정확히 못 읽습니다 |
| 발산 색, 0이 가운데 | 부호가 있는 값이라 |
| 소수 둘째 자리, 앞의 0 생략 | `+.28` |
| n을 칸마다 표기 | §2.2 |
| **연구 표와 사내 표를 절대 한 화면에 섞지 않음** | 하나는 고정값, 하나는 사람 늘 때마다 바뀜 |

마지막 줄이 제일 놓치기 쉽습니다. 두 표는 **탭으로 나누고 제목을 다르게** 답니다 — `연구에서 나온 값` / `우리 회사 데이터`.

### 3.3 산점도

```
  협력
   90 │           ·
      │      ·  ·   ·  ·
   70 │   ·  · ·· ·  ·      ●     ← 마우스 올리면 이름
      │ ·· ·· ·  ·
   50 │  · · ·
      └────────────────────
        40    60    80   인내력
```

| 규칙 | |
|---|---|
| 축 | 양쪽 0~100 고정 |
| 점 | 8px, 슬롯 1 |
| 겹침 | 2px 바탕색 테두리를 둘러 분리 |
| 마우스 | 이름 표시, 클릭하면 개인 상세로 |
| **추세선** | 넣습니다. 단 n 배지와 같이 |

01 §4.5는 산점도에 추세선을 금지했는데, 그건 성향 축끼리라 볼 이유가 없을 때 얘기입니다. 성향 × 직무능력에서는 그 선이 화면의 목적입니다. 대신 **점 50개를 그대로 두는 게 핵심**입니다 — 한두 명이 선을 끌고 있으면 눈으로 보입니다. 상관계수 하나로는 절대 안 보입니다.

### 3.4 순위 막대

직무능력을 눌렀을 때 관련 성향이 순서대로, 그리고 그 역방향에 씁니다.

| 규칙 | |
|---|---|
| 정렬 | 절댓값 큰 순 |
| 부호 | 0을 가운데 두고 좌우로 |
| 색 | 발산 색 (표와 같은 기준) |
| 개수 | **상위 8개까지만.** 나머지는 접어둠 |
| 배지 | 다중비교 경고 상시 |

8개로 자르는 이유가 있습니다. 세부 항목 28개 × 직무능력 3개면 **84개 상관**인데, 아무 관계가 없어도 네댓 개는 우연히 높게 나옵니다. 전부 줄 세워 보여주면 노이즈를 발견으로 읽게 됩니다.

## 4. 화면별 부품 매핑

만들 때 새로 고민하지 않도록 못 박아 둡니다.

### 개인

| | 화면 | 부품 | 가드 |
|---|---|---|---|
| 1 | 7축 결과 | **프로필** + 레이더 | 하나의 눈금에 일곱 축. 기질 4 / 성격 3으로 나눔. 사내 평균 겹치지 않음 |
| 2 | ~~직무능력 3개~~ | — | **개인 화면에서 제외** (D-35). 관리자 전용 |

### 관리자 — 사람 한 명

| | 화면 | 부품 | 가드 |
|---|---|---|---|
| 3 | 7축 + 직무능력 나란히 | 레이더 + 표 | 사내 평균 점선 겹침 |
| 4 | 직무능력 옆 관련 성향 축 | 표 + 분포 막대 | n<30이면 위치 감춤 |

### 관리자 — 전체

| | 화면 | 부품 | 가드 |
|---|---|---|---|
| 5 | 연구 관련도 표 | 상관 표 | 고정값. 탭 분리 |
| 6 | 사내 관련도 표 | 상관 표 + n 배지 | 탭 분리. n<30 잠금 |
| 7 | 직무능력 → 성향 순위 | 순위 막대 | 상위 8개. 다중비교 경고 |
| 8 | 성향 → 직무능력 (역방향) | 순위 막대 | 위와 동일 |
| 9 | 종합 직무능력 | 순위 막대 | 위와 동일 |
| 10 | 산점도 | 산점도 | 추세선 + n 배지 |
| 11 | 계산식 예측 vs 실제 | 산점도 | **과적합 경고 필수** |
| 12 | 사내 분포 | 분포 막대 | n<30 잠금 |
| 13 | 응시 현황 | 숫자 카드 | `n = ? / 50` 상시 |
| 14 | 척도 신뢰도 | 표 + 상태 색 | α<.60 경고 |
| 15 | 대표님 평가 대조 | 산점도 + 표 | 국면이 `결과 공개`일 때만 열림 (D-33) |

**11번을 산점도로 두는 이유** — 예측값과 실제값을 X·Y에 두면 45도 선에서 얼마나 벗어났는지가 바로 보입니다. 오차 숫자 하나로는 어느 사람이 어긋났는지 알 수 없습니다.

## 5. 응시 화면 목업

여기만 그립니다. 데이터가 단순해서 미리 그려도 안 틀리고, 직원 40여 명이 20분씩 보는 화면입니다.

### 5.1 문항 화면 (폭 1024px 이상)

```
+------------------------------------------------------+
|  7차원 성향 설문                          섹션 3 / 7  |
|  ############------------------------                |
+------------------------------------------------------+
|                                                      |
|   14.  처음 맡는 거래처를 배정받으면                   |
|        부담보다 흥미가 앞선다                          |
|                                                      |
|    O      O      O      O      O      *      O       |
|   전혀   아니다  약간    보통   약간  그렇다   매우    |
|  아니다         아니다         그렇다         그렇다   |
|                                                      |
|  --------------------------------------------------  |
|                                                      |
|   15.  마감이 다가오면 평소보다 집중이 잘 된다          |
|                                                      |
|    O      O      O      O      O      O      O       |
|                                                      |
|                                    [ 다음 섹션 ]      |
+------------------------------------------------------+
```

| | |
|---|---|
| 진행률 | 바 + `섹션 N / 7`. 퍼센트·타이머 없음 (01 §2.5) |
| 디밍 | 답할 차례 문항 외에는 글자를 흐리게 |
| 선택 표시 | **색 + 굵기 + 채움** 세 가지 동시 (01 §2.2) |
| 문항 폭 | `max-width: 46rem` — 한 줄 40~50자 |

**섹션은 성향 7축 그대로 7개입니다.** 직무능력 9문항은 별도 섹션으로 몰지 않고 일곱 섹션에 나눠 섞습니다(07·08). 뒤에 몰아두면 "이제 능력 평가구나" 하고 태도가 바뀝니다. 그래서 섹션당 문항이 15개가 아니라 16~17개가 됩니다.

### 5.2 완료 화면

```
+------------------------------------------------------+
|                                                      |
|              응답이 저장되었습니다                     |
|                                                      |
|        114개 문항 · 18분 소요                         |
|                                                      |
|              [ 내 결과 보기 ]                         |
|                                                      |
+------------------------------------------------------+
```

축하 문구나 유형 이름을 넣지 않습니다. 01 §2.9에서 시작 화면을 담백하게 축소한 것과 같은 기준입니다.
