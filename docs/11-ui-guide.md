## 0. 먼저 — 기존 설계와 충돌하는 것 두 개

08·10의 내용을 그대로 넣으려면 `00`·`01`의 확정 사항 두 개를 뒤집어야 합니다. 여기서 결론만 적고, `00`에 정식으로 옮기는 것은 별도로 합니다.

### 충돌 1 — 상관 표시 금지

`01` §4.5와 `00` §6에 이렇게 적혀 있습니다.

> 상관계수·회귀선 **표시 안 함** — n≤50에서 상관 추정은 매우 불안정
> 척도 간 상관분석 ❌ — 50명이면 매우 불안정

그런데 08의 관련도 표, 10의 사내 관련도·순위·계산식이 전부 상관입니다. **핵심 기능이 금지 항목에 걸려 있습니다.**

**결론: 금지를 풉니다. 대신 가드를 UI에 못 박습니다.**

당시 금지한 것은 *성향 축끼리*의 상관이었고, 그건 볼 이유가 없어서 뺀 것입니다. 지금은 *성향 × 직무능력*이고 이게 제품 자체입니다. 다만 **불안정하다는 지적 자체는 그대로 유효합니다.** 그래서 01이 "안 보여줌"으로 피했던 부담을 이 문서가 대신 집니다 — 아래 §2.2의 n 배지와 §3.4의 다중비교 경고는 선택이 아니라 필수입니다.

### 충돌 2 — 개인 화면의 사내 위치

`00` D-09는 **개인 화면에 사내 상대위치를 절대 표시하지 않는다**로 확정돼 있습니다. 이유가 탄탄합니다 — 상대위치는 사람이 늘 때마다 바뀌는데 개인 결과는 스냅샷으로 고정되므로, 30명 근처에서 먼저 본 사람과 나중에 본 사람이 영구적으로 다른 화면을 보게 됩니다.

그런데 `07`의 개인 결과 화면 표에 `능력 | 내 점수 | 사내 위치`가 있습니다.

**결론: D-09를 유지하고 `07`을 고칩니다.**

08이 말하는 "우리 회사 안에서 비교"는 관리자 화면 얘기로 읽으면 충돌이 없습니다. 개인은 원점수와 만점 대비 %만 봅니다.

### 같이 정한 것

**사내 분포 위치를 P2에서 P0으로 올립니다.** 08에 차별점 세 개 중 하나로 적힌 것을 후순위에 둘 수 없습니다. 계산은 정렬 한 번이라 비용도 작습니다. 단 `n < 10`이면 위치 대신 안내 문구를 띄웁니다(D-42, 2026-08-24에 30에서 내림).

## 1. 시각 기반

### 1.1 색

**따뜻한 저채도 팔레트 (2026-08-23 채택).** 차가운 회색 대신 모래 계열을 바탕으로 씁니다.

| 슬롯 | 쓰는 곳 | 값 |
|---|---|---|
| 1 청색 | 본인 · 주 계열 | `#3a5fa0` |
| 2 테라코타 | 사내 평균 · 비교 대상 | `#b3623f` |
| 3 자주 | 셋째가 꼭 필요할 때만 | `#6f5aa8` |

**기본은 둘입니다.** 셋째는 꼭 필요할 때만 쓰고 반드시 글자 라벨을 같이 답니다. 지금 팔레트는 셋 다 검사기를 통과합니다 — 색맹 분리 ΔE `17.6`, 정상 시야 `20.1`.

> **2026-08-24 — 팔레트가 이제 검사기 전 항목을 통과합니다.** 주 계열을 `#44618d → #3a5fa0`, 셋째를 세이지 `#7a8b6d → 자주 #6f5aa8`로 올렸습니다.
>
> 주 계열은 **채도 하한에 걸려 있었습니다**(`0.079`, 기준 `0.10`) — 검사기 표현으로 "회색으로 읽힌다"입니다. 그래서 그래프에서 잘 안 보인다는 말이 나왔습니다. 채도만 올리고 색상(hue)은 그대로 둬서 화면 인상은 유지됩니다.
>
> 셋째는 세이지가 테라코타와 색맹 분리도 ΔE `5.8`, **정상 시야에서도 `12.8`**이었습니다 — 색을 다 보는 사람도 구분하기 어렵습니다. 초록 계열이 테라코타와 붙는 것은 원리상 당연합니다(적록 혼동). 자주로 바꾸니 색맹 `13.8` · 정상 `15.0`으로 통과합니다.
>
> 색상(hue)은 그대로 두고 채도만 올렸으므로 화면 인상은 전과 같습니다. 셋째 색은 지금 화면에서 쓰이지 않지만, 다음에 필요할 때 못 읽히는 색을 집는 일이 없게 미리 맞춰 뒀습니다.
>
> **검사는 눈으로 하지 않습니다.** `dataviz` 스킬의 `validate_palette.js`를 돌립니다 — 밝기 대역·채도 하한·색맹 분리·정상 시야 분리·배경 대비 다섯 가지를 한 번에 봅니다.

**발산 색 — 상관 표 전용**

상관은 −1에서 +1이고 0이 의미 있는 가운데입니다. 단색 계열을 쓰면 **강한 음의 상관이 그냥 "낮은 값"으로 보입니다.** 그래서 양쪽으로 갈라지는 색을 씁니다.

```
  −1                     0                    +1
  테라코타 ◀───────── 모래 ─────────▶ 청회색
  #b3623f            #eae6de            #3a5fa0
```

양쪽 단계 수를 같게 둡니다. 가운데에 색을 넣지 않습니다.

**성향 눈금(낮음↔높음)도 같은 두 색을 쓰되 방향이 반대입니다.** 성향은 낮음이 청회색, 상관은 음이 테라코타입니다. 음의 관계를 따뜻한 색으로 두는 것이 통계 도구의 관행이라 그쪽을 따랐고, **표 아래 범례에 방향을 적어 둡니다.**

**상태 색** — 계열 색과 겹치지 않게 따로 둡니다. 항상 아이콘이나 글자와 같이 씁니다.

| | 값 | 쓰는 곳 |
|---|---|---|
| 양호 | `#0ca30c` | 응답 품질 정상 |
| 주의 | `#fab219` | n 부족, 신뢰구간 넓음 |
| 경고 | `#ec835a` | 다중비교, 과적합 |
| 위험 | `#d03b3b` | 응답 품질 미달 |

**바탕과 글자**

| 역할 | 값 |
|---|---|
| 페이지·카드 바탕 | `#f5f4f0` — 한 톤 |
| 눌러야 할 때 (`--wash`) | `#ede1cb` 모래 |
| 본문 글자 | `#22201d` |
| 보조 글자 | `#56534d` |
| 흐린 글자 (축·라벨) | `#8b877f` |
| 격자선 | `#dfdcd4` |
| 축선 | `#c6c6c8` |
| 테두리 | `rgba(34,32,29,0.13)` |

**다크 모드는 1차 범위 밖입니다.** 다만 색을 전부 CSS 변수로 선언해서, 나중에 값만 갈아끼우면 되게 둡니다.

### 1.2 글자

01 §2.3이 정한 대로 고정 px을 쓰지 않습니다. 글꼴은 `system-ui, -apple-system, "Segoe UI", sans-serif` 하나만 씁니다.

| 역할 | 크기 | 전(8/23) |
|---|---|---|
| 화면 제목 | `clamp(2.25rem, 1.9rem + 1.3vw, 2.875rem)` | 28~36px |
| 구역 제목 | `clamp(1.625rem, 1.4rem + 0.7vw, 2.0625rem)` | 20~26px |
| 문항·해설 본문 | `clamp(1.4375rem, 1.25rem + 0.6vw, 1.75rem)` | 18~22px |
| 일반 본문 | **`1.3125rem`** (21px) | 17px |
| 표 안 글자 | `1.1875rem` (19px) | 15px |
| 축·보조 (가장 작은 글자) | `1.125rem` (18px) | 14px |

**2026-08-24에 눈금 전체를 약 1.3배로 올렸습니다.** 16px에서 17px로 한 번 올렸는데도 계속 작다는 말이 나왔습니다. 사내에서 노트북 배율을 150%로 쓰는 사람이 많습니다(`01` §2.3).

**배수를 칸마다 다르게 주지 않습니다.** 화면별로 1.2배·1.3배를 따로 주면 같은 표가 화면마다 다른 크기로 나오고, 위아래 위계도 무너집니다. 한 번에 올리고 값은 px 정수로 떨어지게 잡았습니다.

**글자만 키우면 안 됩니다.** 같이 손봐야 하는 것들 —

| 같이 키운 것 | 이유 |
|---|---|
| 읽기 폭 `46rem → 56rem` | 폭이 그대로면 한 줄에 들어가는 글자 수가 줄어 줄바꿈이 잦아집니다 |
| 화면 폭 `76rem → 90rem` | 표 열이 넓어진 만큼 가로가 필요합니다 |
| 상관 표 칸 높이 `76 → 100px` | 칸 안에 숫자·등급·n 세 줄이 듭니다 |
| 성향 스트립 칸 `3.25 → 4rem` | 숫자가 커지면 칸도 커져야 합니다 |
| 버튼 높이 `36·44 → 44·52px` | 21px 글자가 36px 버튼에서 위아래로 꽉 찹니다 |
| 입력 높이 `36 → 48px` | 같은 이유 |
| 차트 라벨 `12~17 → 16~22px` | CSS 밖이라 토큰이 안 걸립니다. 컴포넌트마다 맞춥니다 |
| 숫자 타일 `36 → 48px` | 본문이 21px가 되면 36px 숫자는 더 이상 커 보이지 않습니다 |

가장 작은 글자를 18px 아래로 내리지 않습니다 — 여기가 안 읽히면 화면 전체가 답답해집니다.

> **⚠️ 색 토큰과 이름이 겹치면 안 됩니다.** `--color-axis`를 테마에 두면 Tailwind가 `.text-axis`를 **글자색**(`#c6c6c8`)으로도 만듭니다. 같은 이름을 글자 크기 유틸리티로 쓰고 있어서, 색 클래스를 따로 안 붙인 자리는 글자가 배경과 거의 같은 색으로 깔렸습니다. 「숫자가 안 보인다」의 정체가 이것이었습니다. 선·격자에는 `var(--axis)`나 `border-[--axis]`로 직접 씁니다.

**표와 축의 숫자에는 `font-variant-numeric: tabular-nums`를 겁니다.** 자릿수가 세로로 맞아야 훑어볼 수 있습니다. 큰 낱개 숫자(응시 완료 인원 같은 것)에는 걸지 않습니다.

### 1.2.1 화면 폭 — 노트북을 기준으로 잡습니다 (2026-08-24)

글자를 1.3배로 키운 뒤 **좁은 화면에서 여러 곳이 밀려났습니다.** 사무실 노트북이 기준이고, 배율 설정 때문에 실제 CSS 폭은 화면 해상도보다 작습니다.

| 실제 환경 | CSS 폭 | 활성 분기점 |
|---|---|---|
| 1920 · 배율 150% | **1280px** | `xl` 딱 걸림 — 여기가 제일 좁습니다 |
| 1366 노트북 | 1366px | `xl` |
| 1920 · 배율 125% | 1536px | `2xl` |
| 1600 노트북 | 1600px | `2xl` |

**1280px를 최저선으로 잡습니다.** 2단 배치가 켜지는 지점이면서 한 칸이 35rem밖에 안 되는 가장 불리한 조건입니다.

**지켜야 할 것**

| 규칙 | 이유 |
|---|---|
| 고정 폭 격자(`grid-cols-[..rem_..]`)에는 **반드시 좁은 화면용 변형**을 같이 둡니다 | 순위 막대가 `14rem_1fr_16rem`이었는데 1280에서 막대에 3rem만 남았습니다. 막대가 요점인데 그게 먼저 뭉개집니다 |
| 표는 예외 없이 `overflow-x-auto`로 감쌉니다 | 표는 줄일 수 없습니다. 줄이는 대신 스크롤합니다 |
| 칸을 넷 이상 늘어놓을 때는 `flex-wrap`이 아니라 **격자**를 씁니다 | 폭에 따라 3+1로 접혔다 2+2로 접혔다 하면 열 때마다 배치가 달라집니다 |
| `min-w`는 **실제 글자 폭에 맞춰** 잡습니다 | 성향 스트립 칸을 4rem으로 뒀는데 실제 내용은 2.6rem이었습니다. 일곱 칸이면 그 여유가 10rem으로 쌓입니다 |
| 같은 말을 두 번 적지 않습니다 | 리커트 양 끝 안내가 첫·마지막 원 라벨과 똑같았습니다. 15rem을 그냥 먹고 있었습니다 |

**폰까지 확인했습니다 (2026-08-25).** 처음에는 1280px만 봤는데, 그 아래를 재보니 **관리자 상단 메뉴가 화면 밖으로 밀려났습니다** — 다섯 칸에 사용자 영역까지 40rem이 필요한데 폰은 24rem입니다.

| 고친 것 | 어떻게 |
|---|---|
| 관리자 상단 메뉴 | 두 줄로 쌓고 메뉴 줄만 가로로 넘김. **접어 숨기지 않습니다** — 접으면 「지금 이 화면」 표시가 같이 사라집니다 |
| 표 전체 | 가로 스크롤로 둡니다. 표는 줄일 수 없습니다 |
| 개인 결과 | 세 장짜리 보고서(2026-09-18). 양옆 ‹ › 는 종이 바깥 여백이 8px 이상일 때만 나오고, 폰에서는 아래 넘김 줄만 남습니다 |

**응시 화면은 1024px 아래에서 세로 목록으로 바뀝니다.** 7단 가로 배치는 라벨까지 38rem이 필요해서 좁은 화면에서는 펴지 않습니다. 손으로 누르기도 세로가 낫습니다.

### 1.3 간격

4px 단위로만 씁니다. Tailwind 기본 눈금과 같습니다.

`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`

중간값을 만들지 않습니다. 화면마다 간격이 달라지는 원인이 대부분 여기입니다.

### 1.4 데이터 밀도 — 화면마다 반대로 갑니다

이게 이 시스템에서 제일 중요한 판단입니다.

| | 응시 화면 | 관리자 표 |
|---|---|---|
| 보는 시간 | 20분 내리 | 훑어보고 지나감 |
| 한 번에 | 문항 몇 개 | 50명 전부 |
| 행 높이 | 넉넉히 | **32px** |
| 폭 | `max-width` 제한 | 전체 폭 |

관리자 표를 여유 있게(50px) 잡으면 한 화면에 다섯 명밖에 안 들어옵니다. 50명을 훑는 게 목적이므로 조밀하게 갑니다. 반대로 응시 화면을 조밀하게 만들면 20분이 훨씬 길게 느껴집니다.

### 1.5 읽기 폭 제한은 **글자에만** 겁니다

`01` §2.3이 정한 `max-width`는 **글줄 길이 때문**입니다. 한 줄이 길어지면 다음 줄 첫 글자를 찾느라 눈이 헤맵니다. 한국어는 한 줄 40~50자가 상한입니다.

**이 규칙은 글자에만 해당합니다.** 척도 줄, 표, 차트는 글이 아니라서 줄 길이 문제가 없습니다. 같은 컨테이너에 묶으면 넓은 화면에서 가운데만 쓰고 양옆이 비게 됩니다.

```
┌────────────── 페이지 폭 ──────────────┐
│        ┌─ 44rem ─┐                   │
│        │  문 항   │  ← 글자만 제한      │
│        └─────────┘                   │
│  ⬤    ●    ○   ·   ○    ●    ⬤      │  ← 제한 없음
└──────────────────────────────────────┘
```

| 영역 | 폭 |
|---|---|
| 문항·서술문 | `max-width: 44rem` |
| 척도 줄·표·차트 | 컨테이너 전체 |
| 응시 화면 컨테이너 | `80rem` |
| 관리자 | 전체 폭 + 가로 스크롤 |

## 2. 공통 부품

### 2.1 분포 위치 막대

`관리자 개인 상세`, `직무능력 옆 병기`, `사내 분포` 세 군데에서 쓰입니다. **규격이 하나여야 합니다.**

```
협력   75    ▁▁▁▃▅█▇▄▂▁      사내 위치: 위쪽
              └──────┘ ▲
                       이 사람
```

| 규칙 | |
|---|---|
| 축 | 0~100 고정. 자동 눈금 금지 |
| 표현 | `위쪽 / 가운데 / 아래쪽` 세 단계. 백분위 숫자는 안 씁니다 |
| n < 30 | 막대 대신 `아직 비교할 만큼 모이지 않았습니다` |
| 개인 화면 | **표시하지 않음** (D-09) |

세 단계로만 표현하는 이유는 백분위 숫자가 사람이 늘 때마다 흔들려서, 정밀해 보이는 만큼 신뢰를 잃기 때문입니다.

### 2.2 n 배지

상관이 나오는 **모든 자리**에 붙습니다. 예외 없습니다.

```
   +.42                       ← 이렇게 두면 안 됩니다
   +.42  n=43  .13~.64        ← 이렇게 둡니다
```

같은 `.30`이라도 500명이면 확실하고 43명이면 거의 의미가 없습니다. 숫자만 놓으면 보는 사람이 그 차이를 알 수 없습니다.

| 상태 | 표시 |
|---|---|
| 신뢰구간이 0을 안 넘음 | 보통 표시 |
| 0을 넘음 | **흐리게** + 주의 색 점 |
| n < 30 | 값 자체를 감추고 `n 부족` |

### 2.3 경고 배지

계산식 화면과 신뢰도 화면에 붙습니다. 아이콘 + 글자를 같이 씁니다. 색만으로 표시하지 않습니다.

| | 문구 |
|---|---|
| 다중비교 | `탐색용입니다. 우연히 높게 나온 값이 섞여 있을 수 있습니다` |
| 과적합 | `이 회사 데이터로 만든 식이라 실제 오차는 더 큽니다` |
| 신뢰도 미달 | `이 척도는 아직 안정적이지 않습니다` |

### 2.4 세 가지 상태 표기

관련도 표의 칸은 세 상태입니다. **색으로는 뒤 둘을 구분할 수 없으므로 글자로 씁니다.**

| 표기 | 뜻 | 칸 색 |
|---|---|---|
| `+.28` | 연구에서 관련이 나옴 | 발산 색 |
| `없음` | 확인했는데 관련이 없었음 | 중립 회색 |
| `—` | 연구된 적이 없음 | 바탕색 + 흐린 글자 |

### 2.5 그 외

| 부품 | 규격 |
|---|---|
| 버튼 | 높이 44px(주 동작) / 36px(보조). 터치 타깃 44×44 유지 |
| **구역** | **테두리도 바탕색도 두지 않는다.** 제목 + 그 아래 가는 선 + 넉넉한 여백으로만 나눈다 |
| 표 | 감싸는 테두리 없음. 머리행 아래와 행 사이 가로선만 |
| 빈 상태 | 아이콘 없이 한 문장. `아직 응시한 사람이 없습니다` |
| 입력칸 | 여기는 테두리를 남긴다. 어디를 눌러야 하는지가 보여야 한다 |

### 왜 상자를 두르지 않는가

요소마다 테두리와 바탕색을 두면 **화면이 상자 모음으로 보입니다.** 실제로 나뉜 것도 아닌데 나뉜 것처럼 읽히고, 흔한 관리자 템플릿과 똑같아집니다.

### 화면을 두 갈래로 나눕니다 (2026-08-25)

지금까지 규칙 하나를 모든 화면에 똑같이 적용했습니다. 그런데 **하는 일이 다른 화면**에 같은 규칙을 씌우니 어떤 화면은 헐벗어 보였습니다.

| | 어디 | 규칙 |
|---|---|---|
| **읽는 화면** | 랜딩 · 로그인 · 가입 · 응시 · 개인 결과 | 사진·큰 여백·큰 제목을 씁니다. 한 번 읽고 지나가는 자리라 **보통 웹사이트처럼** 만드는 편이 편합니다 |
| **보는 화면** | 관리자 첫 화면 · 구성원 · 분석 · 문항 | 아래 규칙 그대로. 한 톤·가는 선·상자 없음 |

**「보는 화면」의 규칙이 왜 그런가** — 데이터가 빽빽한 자리에서 상자를 두르면 **상자가 데이터보다 먼저 보입니다.** 숫자를 훑는 것이 목적인 화면에서 그건 방해입니다.

**「읽는 화면」은 반대입니다.** 여백과 사진이 읽는 속도를 잡아 줍니다. 사원이 한 번 들어와 결과를 읽고 나가는 자리라 훑을 일이 없습니다.

---

**바탕은 한 톤입니다.** `--page`와 `--surface`가 같은 값(`#fcfcfb`)입니다. 아주 가끔 살짝 눌러야 할 때만 `--wash`(`#f3f2ee`)를 쓰고, 그때도 테두리는 두르지 않습니다.

| 나누는 수단 | 쓰는 곳 |
|---|---|
| **여백** | 기본. 구역 사이 56~80px |
| **제목 + 아래 가는 선** | 구역 머리 |
| 왼쪽 세로선 | 경고·안내처럼 흐름에서 살짝 뺄 때 |
| 옅은 바탕(`--wash`) | 숫자 카드처럼 값이 주인공일 때 |
| ~~감싸는 테두리~~ | **쓰지 않음** |

## 3. 차트 규칙

공통으로 지키는 것 — **선은 2px, 점은 8px 이상, 격자는 흐리게, 값 라벨은 전부가 아니라 골라서.** 계열이 둘 이상이면 범례를 항상 두고, 색 하나로만 구분되게 두지 않습니다.

### 3.1 레이더 — 7축 개인 결과

01 §3.6에 이미 정해져 있습니다. 여기서 더할 것 하나.

**사내 평균을 겹칠 때** 본인은 슬롯 1(파랑) 채움, 사내 평균은 슬롯 2(주황) **점선 테두리만**. 둘 다 채우면 겹친 부분이 안 읽힙니다. 관리자 화면에서만 겹칩니다.

### 3.2 상관 표

가장 중요한 화면입니다.

```
             협력      자율적 실행
  위험회피   −.25       −.36
             n=43       n=43
  사회적     −.34        —
   민감성    n=43
  인내력     +.28       +.14
             n=43       n=43        ← 신뢰구간이 0을 넘으면 흐리게
```

| 규칙 | 이유 |
|---|---|
| 칸 안에 **숫자를 직접** 적음 | 색만으로는 값을 정확히 못 읽습니다 |
| 발산 색, 0이 가운데 | 부호가 있는 값이라 |
| 소수 둘째 자리, **앞의 0을 적는다** | `+0.28` · `0.94` |
| n을 칸마다 표기 | §2.2 |
| **연구 값과 사내 값을 한 표에 섞지 않음** | 하나는 고정값, 하나는 사람 늘 때마다 바뀜 |
| 칸마다 **등급**을 같이 적음 | §3.5 |

마지막에서 둘째 줄이 제일 놓치기 쉽습니다.

**2026-08-24 완화 (D-36).** 원래는 "절대 한 화면에 섞지 않음"이었고 두 표를 탭으로 갈라 뒀습니다. 그러니 **맞는지 확인할 방법이 없다**는 지적이 나왔습니다 — 탭을 오가며 14칸을 외워 맞대야 했습니다.

지금은 **한 화면에 세 절로 세로로 쌓습니다.**

```
  1  우리 회사 데이터    ← 우리 사람 이야기가 먼저
  2  연구에서 나온 값    ← 같은 7×3 격자라 모양이 눈으로 맞대집니다
  3  얼마나 맞는가       ← 스크롤을 내리면 나오는 대조표
```

**금지선은 표 단위로 옮겨졌을 뿐 사라지지 않았습니다.** 두 값을 한 칸에 합치거나 평균 내지 않습니다 — 표본도 지표도 나라도 달라서 합치면 없는 숫자를 만들어내는 셈입니다. 3절에서도 칸끼리 **나란히 놓기만** 합니다.

**대조 판정은 차이값으로 하지 않습니다.** 사내 값은 사람이 적어 원래 흔들립니다. `연구값이 사내 95% 신뢰구간 안에 들어오는가`로 판정하고, 들어오면 `들어맞음`, 벗어나면 `어긋남`으로 적습니다. 사람이 늘어 구간이 좁아질수록 판정이 날카로워집니다.

### 3.2.1 칸을 작은 그래프로 (2026-08-24)

색 하나가 **방향과 크기를 다 지고** 있었습니다. 그러면 `+.31`과 `+.44`가 얼마나 다른지 눈으로 안 읽히고, 색을 못 보는 사람에게는 아무것도 안 남습니다.

칸 안에 **0을 가운데 둔 막대**를 깝니다.

```
┌──────────────┐
│    뚜렷함     │  등급
│  ──┃▓▓▓▓──   │  막대 — 칸의 가운데. 길이가 크기, 좌우가 방향
│    +.31      │  값
│    n=37      │  표본
└──────────────┘
```

**막대가 칸의 가운데입니다.** 표를 훑을 때 먼저 잡혀야 하는 것이 「얼마나 큰가」이고, 숫자는 그다음에 확인하는 것입니다.

| 채널 | 무엇을 말하나 |
|---|---|
| **막대 길이** | 관련도 크기 |
| **막대 좌우** | 방향 |
| **막대 흐림** | 신뢰구간이 0을 걸침 |
| 배경색 | 방향(보조) — 섞임 `0.6 → 0.32`, 바닥 `0.12 → 0.06`으로 물러남 |

**색 세기를 등급 경계에 맞춥니다 (2026-08-24).** 전에는 `|r|`을 `0~0.7`에 선형으로 폈는데, 실제 값이 대부분 `.5` 아래에 몰려 있어 **쓰이는 구간이 좁았습니다** — `.12`짜리 칸과 `.38`짜리 칸이 거의 같은 색이었습니다. 지금은 등급 경계마다 색이 한 단씩 올라가게 꺾어 둡니다.

| `\|r\|` | 0 | .10 | .20 | .30 | .50+ |
|---|---|---|---|---|---|
| 섞임 | `.05` | `.14` | `.24` | `.34` | `.46` |
| 등급 | 없음 | 약함 | 어느 정도 | 뚜렷함 | 매우 뚜렷함 |

색과 등급이 **같은 이야기**를 하게 되고, 값이 몰려 있어도 칸끼리 갈립니다. 가장 진한 `.46`에서도 본문 잉크와 `6.8:1`로 벌어져 칸 안 글자가 읽힙니다.

> **등급 경계 자체(`.10`/`.20`/`.30`/`.50`)는 건드리지 않았습니다.** 그 값은 개인차 연구 상관 708개의 실제 분포에서 온 것입니다(§3.5). 색이 잘 안 갈린다고 근거 있는 기준선을 옮기면 안 됩니다 — **색을 기준선에 맞추는 것**이 순서입니다.

**칸 사이는 띄우지 않고 선으로 나눕니다 (2026-08-24).** 전에는 2px씩 벌리고 칸마다 안쪽 그림자로 테두리를 흉내 냈는데, 그러면 **선이 칸마다 끊겨서 가로세로로 이어지지 않습니다** — 표를 훑을 때 눈이 줄을 따라가지 못합니다. `border-collapse`로 붙이고 1px 선을 그으면 격자가 끝까지 이어집니다.

선이 칸의 경계를 지므로 **배경색은 더 옅어져도 됩니다.** 21칸이 전부 칠해져 있으면 표 전체가 어두운 덩어리로 보입니다. 가운데 색도 `#ddd8ce → #eae6de`로 올렸습니다.

**배경색을 옅게 내린 것이 핵심입니다.** 한 정보를 두 채널이 세게 겹쳐 지면 칸이 시끄럽고 글자도 안 읽힙니다. 막대가 앞에 서고 색은 물러납니다.

막대 규칙은 순위 화면·대시보드와 **같습니다.** 같은 값이 화면마다 다른 모양이면 눈이 다시 배워야 합니다.

### 3.5 상관 등급

`+.31` 하나만 놓으면 큰지 작은지 알 수 없습니다. **숫자 옆에 등급을 같이 답니다.**

| 값 | 등급 |
|---|---|
| `.50` 이상 | 매우 뚜렷함 |
| `.30`~`.49` | 뚜렷함 |
| `.20`~`.29` | 어느 정도 |
| `.10`~`.19` | 약함 |
| `.10` 미만 | 없음 |

**경계를 Cohen(.10/.30/.50)으로 잡지 않습니다.** Cohen은 실험 연구 기준이라 개인차를 다루는 자리에서는 너무 높습니다 — 성격 연구에서 `.50`을 넘는 일이 사실상 없어 쓸 만한 관계가 전부 `약함`으로 깎여 보입니다. Gignac & Szodorai(2016)가 개인차 연구 상관 708개에서 본 실제 분포(25% `.11` · 중앙값 `.19` · 75% `.29`)를 따라 `.10`/`.20`/`.30`으로 잡았습니다.

**신뢰구간이 0을 걸치면 등급 대신 `불확실`을 답니다.** 세기를 말하려면 방향이 먼저 정해져야 합니다.

### 3.3 산점도

```
  협력
   90 │           ·
      │      ·  ·   ·  ·
   70 │   ·  · ·· ·  ·      ●     ← 마우스 올리면 이름
      │ ·· ·· ·  ·
   50 │  · · ·
      └────────────────────
        40    60    80   인내력
```

| 규칙 | |
|---|---|
| 축 | 양쪽 0~100 고정 |
| 점 | 8px, 슬롯 1 |
| 겹침 | 2px 바탕색 테두리를 둘러 분리 |
| 마우스 | 이름 표시, 클릭하면 개인 상세로 |
| **추세선** | 넣습니다. 단 n 배지와 같이 |

01 §4.5는 산점도에 추세선을 금지했는데, 그건 성향 축끼리라 볼 이유가 없을 때 얘기입니다. 성향 × 직무능력에서는 그 선이 화면의 목적입니다. 대신 **점 50개를 그대로 두는 게 핵심**입니다 — 한두 명이 선을 끌고 있으면 눈으로 보입니다. 상관계수 하나로는 절대 안 보입니다.

### 3.4 순위 막대

직무능력을 눌렀을 때 관련 성향이 순서대로, 그리고 그 역방향에 씁니다.

| 규칙 | |
|---|---|
| 정렬 | 절댓값 큰 순 |
| 부호 | 0을 가운데 두고 좌우로 |
| 색 | 발산 색 (표와 같은 기준) |
| 개수 | **상위 8개까지만.** 나머지는 접어둠 |
| 배지 | 다중비교 경고 상시 |

8개로 자르는 이유가 있습니다. 세부 항목 28개 × 직무능력 3개면 **84개 상관**인데, 아무 관계가 없어도 네댓 개는 우연히 높게 나옵니다. 전부 줄 세워 보여주면 노이즈를 발견으로 읽게 됩니다.

| 4 | 직무능력 옆 관련 성향 축 | 표 + 분포 막대 | n<30이면 위치 감춤 |

### 관리자 — 전체

| | 화면 | 부품 | 가드 |
|---|---|---|---|
| 5 | 연구 관련도 표 | 상관 표 | 고정값. 탭 분리 |
| 6 | 사내 관련도 표 | 상관 표 + n 배지 + 등급 | ~~탭 분리~~ → **한 화면에 세로로 쌓음** (D-36). n<10 잠금 (D-42) |
| 7 | 직무능력 → 성향 순위 | 순위 막대 | 상위 8개. 다중비교 경고 |
| 8 | 성향 → 직무능력 (역방향) | 순위 막대 | 위와 동일 |
| 9 | 종합 직무능력 | 순위 막대 | 위와 동일 |
| 10 | 산점도 | 산점도 | 추세선 + n 배지 |
| 11 | 예측 대 실제 | 산점도 + 차이 막대 | **논문 값으로 예측** (D-44). 대각선은 `y=x` 기준선이지 추세선이 아님 |
| 12 | 사내 분포 | 분포 막대 | n<10 잠금 (D-42) |
| 13 | 응시 현황 | 숫자 카드 | `n = ? / 50` 상시 |
| 14 | 척도 신뢰도 | 표 + 상태 색 | α<.60 경고. **기질·성격·직무능력 세 표로 분리.** 사람별 응답 신뢰도는 별도 절 |
| 15 | ~~관리자 평가 대조~~ | — | 관리자 평가와 함께 걷어냄 (2026-09-18) |

**11번을 산점도로 두는 이유** — 예측값과 실제값을 X·Y에 두면 45도 선에서 얼마나 벗어났는지가 바로 보입니다. 오차 숫자 하나로는 어느 사람이 어긋났는지 알 수 없습니다.

**선을 둘 그립니다 (2026-08-24).**

| 선 | 뜻 |
|---|---|
| 회색 점선 · 기울기 **1.00** | 논문 예측이 그대로 맞았다면 |
| 파란 실선 · 기울기 **r** | 실제로 나타난 기울기 |

대각선 하나만 두면 「얼마나 벗어났나」는 보이지만 **실제 기울기가 몇인지**는 안 보입니다. 두 선 사이가 벌어진 정도가 곧 "논문이 본 차이 중 얼마가 실제로 나타났는가"입니다 — 기울기 `0.35`면 3분의 1쯤입니다.

> **45도 선은 추세선이 아닙니다.** `y = x`, 곧 「예측과 실제가 똑같다」는 기준선입니다. 데이터로 그은 선을 같이 그리면 두 선이 헷갈리므로 그리지 않습니다. 예측값 자체는 **논문 상관을 가중치로 쓰되 눈금은 우리 데이터에서 빌려** 만듭니다 (D-44).

## 5. 응시 화면 목업

여기만 그립니다. 데이터가 단순해서 미리 그려도 안 틀리고, 직원 40여 명이 20분씩 보는 화면입니다.

### 5.1 문항 화면 (폭 1024px 이상)

```
+------------------------------------------------------+
|            설문 진행도   3 / 7 묶음                    |
|            ############--------------                |
+------------------------------------------------------+
|                                                      |
|   14.  처음 맡는 거래처를 배정받으면                   |
|        부담보다 흥미가 앞선다                          |
|                                                      |
|    O      O      O      O      O      *      O       |
|   전혀   아니다  약간    보통   약간  그렇다   매우    |
|  아니다         아니다         그렇다         그렇다   |
|                                                      |
|  --------------------------------------------------  |
|                                                      |
|   15.  마감이 다가오면 평소보다 집중이 잘 된다          |
|                                                      |
|    O      O      O      O      O      O      O       |
|                                                      |
|                                    [ 다음 섹션 ]      |
+------------------------------------------------------+
```

| | |
|---|---|
| 진행률 | 「설문 진행도」 + `N / 7 묶음` + 가는 바, 가운데 2/3 폭 (2026-09-18). 퍼센트·타이머 없음 (01 §2.5) |
| 디밍 | 답할 차례 문항 외에는 글자를 흐리게 |
| 선택 표시 | **색 + 굵기 + 채움** 세 가지 동시 (01 §2.2) |
| 문항 폭 | `max-width: 46rem` — 한 줄 40~50자 |

**섹션은 성향 7축 그대로 7개입니다.** 직무능력 9문항은 별도 섹션으로 몰지 않고 일곱 섹션에 나눠 섞습니다(07·08). 뒤에 몰아두면 "이제 능력 평가구나" 하고 태도가 바뀝니다. 그래서 섹션당 문항이 15개가 아니라 16~17개가 됩니다.
