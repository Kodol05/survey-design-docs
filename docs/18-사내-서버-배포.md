# 사내 서버에 올리기

> 2026-09-30 작성. 서버 한 대에 **DB와 앱을 도커로 같이** 올립니다. 50명·12MB 규모라 이 구성으로 충분합니다.

## 준비물

- 리눅스 서버 한 대 (1~2코어, 메모리 2GB면 충분)
- Docker와 Docker Compose
- 서버에서 GitHub 저장소를 받을 수 있을 것

Node.js는 서버에 깔지 않아도 됩니다. 앱 이미지 안에 들어 있습니다.

## 처음 올릴 때

```bash
git clone https://github.com/Kodol05/survey-design-docs.git
cd survey-design-docs

# 1. DB 비밀번호 — 새로 정한다. 개발용 기본값이면 앱이 켜지지 않는다
cp .env.example .env            # POSTGRES_PASSWORD= 에 새 비밀번호

# 2. 앱 설정
cp web/.env.example web/.env    # ADMIN_INITIAL_PASSWORD 를 바꾼다
                                # HTTPS 로 여는 서버면 COOKIE_SECURE=1 도

# 3. 켜기 — DB 와 앱이 같이 뜨고, 앱이 켜질 때 표를 만든다
docker compose up -d --build

# 4. 문항과 관리자 계정 넣기 (처음 한 번)
docker compose exec app npm run db:seed
```

이제 `http://서버주소:3000` 으로 열립니다. 관리자는 `/admin/login`.

## 코드를 고친 뒤 반영

```bash
git pull
docker compose up -d --build
```

앱이 다시 켜질 때 밀린 마이그레이션을 스스로 적용합니다. 데이터는 DB 볼륨에 있어 그대로 남습니다.

## 알아 둘 것

| | |
|---|---|
| **자동 재시작** | 앱이나 DB가 죽거나 서버가 재부팅되면 도커가 다시 켭니다 (`restart: unless-stopped`) |
| **DB 접속 문** | DB(5432)는 서버 안에서만 열립니다. 사내망에서 DB에 직접 붙을 수 없습니다 |
| **DB 비밀번호** | DB를 **처음 만들 때** 정해집니다. 나중에 `.env` 만 바꾸면 앱이 못 붙습니다. 바꾸려면 DB 안에서 `ALTER USER survey PASSWORD '…'` 도 같이 합니다 |
| **HTTP / HTTPS** | 기본은 HTTP로 로그인이 됩니다. 앞에 HTTPS(사내 인증서, Caddy·nginx 등)를 붙이면 `web/.env` 에 `COOKIE_SECURE=1` |
| **백업** | 루트 `backups/` 에 쌓입니다. 관리자 15벌 + 설문 제출 30벌 ([13 백업·복구](13-backup-restore.md)). 서버 밖 사본은 대시보드의 「백업 파일 받기」로 |
| **가입** | 누구나 가입할 수 있고 상한은 200명입니다 (`lib/auth/signupCap.ts`) |
| **시험용 DB** | `docker compose up` 으로는 뜨지 않습니다. 개발 PC에서 `npm run db:test:up` 으로만 |

## Vercel·Neon 에서 옮겨 올 때

지금 Vercel에 쌓인 응답을 가져오려면, Neon 에서 덤프를 떠서 사내 DB 에 붓습니다.

```bash
# Neon 주소(.env.vercel 의 DATABASE_URL_UNPOOLED)로 덤프 — pg_dump 16 이상 필요
docker run --rm postgres:16-alpine pg_dump "<Neon 주소>" --clean --if-exists --no-owner --no-privileges | gzip > neon.sql.gz

# 사내 DB 에 붓기 — 앱은 먼저 멈춘다
docker compose stop app
gunzip -c neon.sql.gz | docker compose exec -T db psql -U survey -d survey -v ON_ERROR_STOP=1
docker compose start app
```

붓기 전에 [13 백업·복구](13-backup-restore.md) §3 처럼 시험용 DB에 먼저 부어 행 수를 확인하시길 권합니다. 문항 문구를 바꾼 뒤라면 `docker compose exec app npx tsx scripts/apply-item-content.mts` 로 문구만 다시 반영합니다 (응답은 손대지 않습니다).
