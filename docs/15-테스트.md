# 테스트

두 갈래입니다. 성격이 달라서 나눠 뒀습니다.

```bash
npm test        # 269개 중 252개 · DB 없이 2초
npm run test:db # 17개 · 시험용 DB 에 붙어서
```

| | 무엇을 확인하나 | DB |
|---|---|---|
| `npm test` | 계산·규칙 — 채점, 통계, 문구, 밝기, 화면 자물쇠 | 안 씀 |
| `npm run test:db` | **저장하고 이어받는 것** — 답이 남나, 덮어쓰나, 통째로 취소되나 | 씀 |

고치는 중에는 `npm test`만 계속 돌리시면 됩니다. 2초라 부담이 없습니다. 설문 저장 쪽을 건드리셨을 때만 `npm run test:db`를 같이 돌리세요.

## 처음 한 번 — 시험용 DB 세우기

```bash
npm run db:test:up        # 컨테이너 띄우기 (포트 5433)
npm run db:test:migrate   # 표 만들기
```

`.env.test`가 있어야 합니다. `web/.env.example`을 보고 만드시되 **포트를 5433, DB 이름을 `survey_test`로** 두세요.

```
DATABASE_URL="postgresql://survey:devpassword@localhost:5433/survey_test?schema=public"
```

## 왜 DB 를 따로 두나

이 테스트들은 **표를 통째로 비우고 시작합니다.** 매번 0에서 시작해야 「한 묶음을 저장하면 세 개가 남는다」를 확인할 수 있기 때문입니다.

그걸 진짜 DB 에서 하면

- 가짜 사람이 쌓여 **분석 결과가 흔들리고**
- 지금 누가 응시 중이면 **세는 숫자가 시험 도중에 바뀌고**
- 무엇보다 **지우는 조건을 한 글자 틀리면 진짜가 날아갑니다**

시험용 DB 는 진짜와 **포트도 저장 공간도 완전히 따로**입니다. 서로 닿을 수 없습니다.

### ⚠️ 안전장치

`src/test/db-setup.ts`가 **접속하기 전에** 주소를 뜯어봅니다. 셋 중 하나라도 안 맞으면 아예 멈춥니다.

- 포트가 `5433`
- DB 이름이 `survey_test`
- `localhost` 또는 `127.0.0.1`

실제로 진짜 DB(5432)를 가리켜 보고 막히는 것을 확인했습니다.

```
✖ 시험용 DB 가 아닙니다. 표를 비우는 테스트라 여기서 멈춥니다.
    지금  localhost:5432/survey
    필요  localhost:5433/survey_test
```

## ⚠️ 통과하는 테스트가 곧 지켜지는 테스트는 아니다

이 파일을 만들면서 실제로 겪은 일입니다.

「하나라도 잘못되면 통째로 저장하지 않는다」를 확인하는 테스트를 썼습니다. 통과했습니다. 그런데 **`$transaction` 을 `Promise.all` 로 바꿔 놓아도 그대로 통과했습니다.**

값 검사가 DB 에 닿기 **전에** 다 걸러내기 때문입니다. 잘못된 값으로는 저장 경로를 아예 안 지나니, 그 경로가 한 덩어리인지 아닌지는 확인되지 않았던 것입니다.

**DB 만 잡을 수 있는 실패**(없는 문항을 가리키는 답)로 바꾸고 나서야 제대로 잡혔습니다.

### 그래서 새 테스트를 넣을 때는

**일부러 망가뜨려 보고 빨개지는지 확인합니다.** 네 가지를 시험해 봤습니다.

| 망가뜨린 것 | 잡히나 |
|---|---|
| `upsert` → `create` (다시 답하면 줄이 늘어남) | ✅ |
| 14일 정리에서 「진행 중만」 조건 제거 | ✅ |
| `$transaction` → `Promise.all` | ✅ (고친 뒤) |
| 하던 세션을 안 이어받음 | ✅ |

## 파일 이름 규칙

- `*.test.ts` — DB 없이. `npm test` 가 집어갑니다
- `*.db.test.ts` — DB 를 씁니다. `npm run test:db` 만 집어갑니다

`vitest.config.mts` 가 `*.db.test.ts` 를 **일부러 뺍니다.** 안 빼면 DB 주소도 없이 열려다 터집니다.
