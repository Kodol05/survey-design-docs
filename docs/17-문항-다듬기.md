# 문항·해석 다듬기 — 실제 설문 말투로

> **상태: 완료 (2026-09-18).** `data/items/v1.yaml` 의 문항 120개를 세 차례에 걸쳐 고쳐 쓰고
> (`v1` 을 덮어씀, 새 판 없음), `scripts/apply-item-content.mts` 로 운영 DB 에 반영했다.
> 응답 데이터는 손대지 않았다. 해석 문구(`lib/interpretation`)도 같은 결로 다시 썼다.
> 아래는 그때의 계획이다.

## 왜

문항 뜻은 대체로 맞는데 **문장 결이 서술적·구어적**이라, 실제 자기보고 설문
문항처럼 담백하게 읽히지 않는 곳이 있다. 뜻은 그대로 두고 **설문 문항다운
말투**로 다듬고, 그 김에 약한 문항(모호·이중질문·구성개념 부적합·사회적
바람직성 편향)은 고치거나 바꾼다. 해석 텍스트도 같은 결로 손질한다.

## 근거·저작권

- 근거는 **IPIP(공개 도메인) 프록시**와 각 축의 구성개념 정의다. 파일이
  이미 이 방식을 따른다(각 축 머리말에 IPIP 프록시·상관 표기).
- **공식 척도(TCI-RS 등)·그 한국어 번역본을 그대로 옮기지 않는다.** 방향만
  보고 우리 한국어로 쓰고 `sourceRef`를 남긴다. (00 §5)

## 다듬는 말투 (목표 결)

- **1인칭 평서문, 한 문항 한 내용.** 이중질문·조건절 남발을 없앤다.
- **담백하게.** 장면을 길게 그리기보다 핵심 성향을 곧장 묻는다. 다만
  기질 축은 절반쯤, 성격 축은 대부분 **직장 맥락**을 유지한다(08 — 맥락형이
  직무성과를 더 잘 예측). 맥락은 남기되 문장을 짧고 곧게.
- 유도·이중부정·전문용어를 피하고, 사회적 바람직성으로 한쪽 답이 뻔한
  문장은 고친다.
- 종결은 기존대로 `~다` / `~하는 편이다`.

## 유지하는 것 (구조·규칙)

- 1–7점 · 7묶음 · 총 120(성향 105 + 직무 15) · 직무 축당 5(직접 1 + 간접).
- 역방향 비율 25~45%, 짝(`antonymOf`)은 서로를 가리키고 방향이 반대.
- `sourceRef` 필수, 응시 화면에 `isReverse`·`scale` 미노출.
- `code`·`orderNo`·`scale`·`subscale`·축 구성·`kind`는 그대로. **문장과
  필요 시 역방향 균형만** 손댄다. 검사는 `src/lib/items/validate.ts`.

## 버전 (사용자 결정: v1 덮어쓰기)

- `data/items/v1.yaml`을 고치고 v1을 다시 시드한다. seed 가드(응답 존재 시
  중단)를 피하려면 **문항 문구만 갱신하는 통제된 경로**를 쓴다 — 응답·결과는
  지우지 않고 `Item`만 code 기준으로 갱신. 기존 응답은 남되 다시 채점하면
  값이 달라진다(문항 수정 경고와 같은 성격, `admin/items` 참고).

## 단계

1. 성향 7축(105문항) 말투 다듬기 + 약한 문항 손질 — 축 단위로.
2. 직무능력 3축(15문항).
3. 해석 텍스트(`poles`·`bands`·`apply`·`pairs`) 말투·구조 손질
   (`writing.test` 통과 유지).
축마다: YAML 갱신 → `loadItemFile` 검사 통과 → 로컬 확인 → 반영.

## 검사

- `loadItemFile`(개수·역방향 비율·짝·`sourceRef`·중복 code) 통과.
- 해석은 `writing.test`(말투·완결성) 통과.
- 축 단위 before/after 로 결을 확인하며 진행.
